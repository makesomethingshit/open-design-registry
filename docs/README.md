# 문서 목차

[프로젝트 소개와 빠른 시작](../README.md)

필요한 작업에 맞는 기준 문서부터 읽습니다. 현재 구현, 제품 원칙, 장기 비전은 구분하며, 같은 계약을 여러 문서에서 다시 정의하지 않습니다.

## 제품을 이해하거나 사용하기

| 문서 | 다루는 내용 |
| --- | --- |
| [현재 기능과 제품 경계](current-capabilities.md) | 구현된 기능, 공개 탐색과 개인 작업 공간, 지원하지 않는 범위 |
| [Proposal 협업 가이드](proposals.md) | 기여 준비·리뷰·선택 적용, 상태·충돌·승인 해제와 알림 |
| [제품 방향](product-direction.md) | 프로젝트 중심 협업과 발견에 관한 제품 원칙 |
| [로드맵](../ROADMAP.md) | 남은 개선 과제와 장기 검토 항목 |
| [Vision](../VISION.md) · [Philosophy](../PHILOSOPHY.md) | 장기 생태계의 목표와 출처·저자성·공개의 철학 |

처음 제품을 이해한다면 현재 기능 → 제품 방향 → 필요한 협업 가이드 순으로 읽습니다. 장기 목표는 현재 지원 기능과 구분해서 읽습니다.

## 문서를 갱신할 때

- 기능의 지원 여부는 현재 기능 문서, 남은 작업은 로드맵에서 갱신합니다.
- 서버 계약은 구조와 데이터 모델, Proposal의 작업·리뷰·적용 계약은 협업 가이드에 둡니다.
- 명령과 환경 변수는 개발과 운영, UI 구현 규칙과 문구는 디자인 시스템과 용어집에 둡니다.
- 다른 문서는 해당 기준 문서로 연결합니다. 구현·테스트 코드가 바뀌면 관련 설명도 함께 대조하며, 코드 기준과 실제 실행·배포 확인을 구분합니다.
